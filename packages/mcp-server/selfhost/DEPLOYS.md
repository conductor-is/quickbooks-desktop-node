## 2026-10-30: stop abandoned executes, trace each call, explain API errors

- Deploy: dep-dbi2lrks728c73a08umg, commit b65f24a (PR #262, five changes from the 2026-10-28 audit in three commits: the feature, a formatting fix and the built-in code review's fixes), live 2026-10-30T05:30Z; both instances (hostnames ending `59cnq` and `vphrp`) logged "MCP Server running" at 05:29:58Z. No npm release was needed: the hosted service builds from the repo on Render and the npm package's stdio bridge only relays to mcp.conductor.is, so release-please keeps accumulating (open release PR #252, 14.25.0).
- Tool description: the `execute` description, which every client sees in `tools/list`, carries four rules: get `conductorEndUserId` from `endUsers.list()`, never guess it; one request at a time, never `Promise.all`, batching only ids an earlier call returned; keep each tool call under about a minute (some clients stop waiting at 60 s, and a timed-out call returns only the error); in a loop of writes, stop at the first new QuickBooks Desktop error and never resend a rejected request unchanged. About 740 bytes more per `tools/list`.
- Abort on client disconnect: `http.ts` registers `res.on('close')` before any await and closes the transport, the MCP SDK (1.27.1, `Protocol._onclose`) aborts the handler's `extra.signal`, and `code-tool.ts` races the Deno worker against that signal and terminates it. A call whose client already left (including during the gate's key probe, caught through `res.closed`) takes no execution slot. The `notifications/cancelled` half (mcp-remote keeps the POST open) stays in TODO.
- Call tracing: each execute call gets a UUID, sent on every API request its code makes as `Conductor-MCP-Call-Id`, with `Conductor-MCP-Session-Id` (the client's `mcp-session-id`, sanitized) and `Conductor-MCP-Client` (the User-Agent reduced to printable ASCII, 120 chars). The "Got code tool execution result" line carries `mcpSessionId`, `callId`, `tool`, `userAgent` and, on failure, `errorKind` (fixed labels: `blocked_method`, `client_closed`, `timeout`, `no_deno`, `no_run_function`, `ts_diagnostics`, `api_error:<CODE>`, `api_error`, `api_connection_error`, `runtime_error`, `unknown`; never result text); for an abandoned call it is at warn with `abortedBy: client_closed`. Every pino-http request line carries `rpcMethod` and, for `tools/call`, `tool`.
- API errors: inside the Deno worker, `makeStatusError` on the SDK client's prototype is wrapped so an API error's message reads `<CODE>: <message> (HTTP <status>, request <id>)`, plus one next-step hint for the connection-error family, `INTEGRATION_CONNECTION_NOT_SET_UP`, a missing or unknown end-user id, and other `INVALID_REQUEST_ERROR`s; QuickBooks rejections, `API_KEY_INVALID` and `INTERNAL_ERROR` get none. Class, status, headers and body are untouched. The worker prints `Error: <CODE>: ...` because the SDK's classes leave `name` as `Error`.
- Gate rejections: every "OAuth gate rejected request" line carries `credentialShape` (`empty_bearer`, `scheme:<word>`, `no_scheme:sk_conductor_`, `no_scheme:other`, `empty_custom_header`; never any part of the value), `rpcMethod`, `userAgent` (100 chars) and `resource`. A bare `sk_conductor_` key is still rejected; accept it only if the shape log shows that is the failing claude.ai connector's shape.
- Verified on production after both instances rolled: `tools/list` returns the new description. A `curl --max-time 5` `tools/call` whose code sleeps 60 s (production key, UA `conductor-postdeploy-check/1`) produced, 0.35 s after curl gave up, a warn-level result line with `errorKind: client_closed`, `abortedBy: client_closed`, `durationMs: 4652`, `callId` and `userAgent`, and its request line carried `tool: execute` and `rpcMethod: tools/call`, which proves Render's edge passes client disconnects to the origin. A POST with `Authorization: Basic eDp5` was 401 with the gate line `oauthGate: invalid_scheme`, `credentialShape: scheme:basic`, `rpcMethod: initialize`, `resource: root`.
- Logs: `render logs -r srv-da3mnkbbc2fs73acu8t0 --text abortedBy` (abandoned calls, one warn line each with `durationMs`); `--text errorKind` (every failed execute by category); `--text credentialShape` (what a rejected Authorization header looked like); `--text "Got code tool execution result"` lines now join the request line by `mcpSessionId` and the API side by `callId`.
- API side: in Better Stack source 214704, every API request an execute sandbox makes carries the request headers `conductor-mcp-call-id`, `conductor-mcp-session-id` and `conductor-mcp-client`, so `raw LIKE '%conductor-mcp-call-id%'` selects MCP-relayed traffic and `JSONExtractString(raw,'request','headers','conductor-mcp-call-id')` groups it by call.
- Kill switches: `CONDUCTOR_MCP_ABORT_ON_CLOSE=off` (a disconnected client's code runs to completion or the timeout, as before) and `CONDUCTOR_MCP_AGENT_ERRORS=off` (read on the host and passed in the worker request; the model sees the SDK's own error text again). Add either to the conductor-mcp `envVars` in `render.yaml` on `production` the same way as `CONDUCTOR_MCP_KEY_PROBE` (2026-10-26 entry).
- stlc and tests: sealed hunks in the generated `code-tool.ts`, `code-tool-worker.ts`, `http.ts`, `server.ts` and `types.ts`; new custom files `src/telemetry.ts` and `src/agent-errors.ts` (`src/oauth.ts` was already custom); guarded by `tests/conductor-patches.test.ts`. Locally, `cd packages/mcp-server && node tests/patches-smoke.mjs` (needs a built dist and Deno) boots the server against a mock API, abandons a 60 s execute after 2 s and expects it to stop within seconds with its slot free, then checks the rewritten error, the hint, the three headers at the mock API and the `errorKind`.
